# Контракты ядра перед распределением работы

- `StartOrder` раньше принимал готовый снимок самоката. Это оставляло порядок проверки повтора, чтения оффера и обращения к Source на стороне HTTP. Теперь сервис заказа сначала ищет повтор, затем читает оффер и получает снимок вне транзакции. При отказе Source сервис повторно ищет заказ, созданный параллельно. В транзакции он повторяет проверки под блокировками.
- Для исчерпанного START добавлен `ExhaustStart` в сервисе заказа. Проверка лимита, lease и дедлайна идёт под блокировками. Приоритет у дедлайна. Существующая транзакция закрытия одновременно завершает задачу, при необходимости закрывает заказ и ставит VOID при положительном депозите.
- Изменены пакеты `offer`, `order` и `task` в Rental. В интеграционных тестах заказа проверены отказ Source и параллельный повтор, активная последняя попытка, истёкший lease и приоритет дедлайна. Миграции и конфигурация Compose сохранены.
- `WORK_SPLIT.md` распределяет сценарии между офферами и Source, API заказов, worker и Payment, maintenance и историей. В документе указаны критерии приёмки и правила изменений.
- Интеграционные тесты Rental с детектором гонок на PostgreSQL 17, `go vet` и `go build` прошли. Тесты трёх модулей через `go.work` прошли. Независимая сверка с ADR и тест-планом не выявила блокирующих замечаний.
- В срезах остаются HTTP-обработчики, клиенты Source и Payment, захват задач и циклы worker и maintenance. Сквозные и нагрузочные сценарии проверяются после их подключения. Операций с Git не было.
