# Разделение на Go-модули

## Задача

Пользователь подтвердил три самостоятельных Go-модуля для Rental, Source и Payment. Каждый владеет своим запуском, сборкой образа и миграциями своей БД. Корневой go.work объединяет локальную разработку.

## Изменения

- Перенесли единственный корневой Go-каркас в services/rental и перенесли начальную SQL-миграцию без изменения
- Выделили в Rental пакеты config, offer, order и task. Операции записи внутри разных пакетов используют транзакцию прикладного сценария. Заказ и задача START либо SETTLE фиксируются вместе
- Создали отдельные модули и точки запуска Source и Payment. По контрактам проекта они используют память процесса
- Настроили Compose на независимые контексты сборки и применение миграций перед запуском Rental. Обновили инструкции запуска

## Проверки

- GOWORK=off, go test -race, go vet и отдельная сборка для каждого Go-модуля
- Интеграционные тесты Rental на PostgreSQL 17.11. Проверены повтор старта, конкурентная аренда одного самоката, отклонение позднего результата после дедлайна и повтор завершения после переноса
- Общий запуск тестов из корня через go.work. Сборка трёх образов, запуск Compose, health и metrics трёх сервисов, ready Rental и код 0 мигратора. В goose_db_version подтверждена версия 1
- Независимая проверка архитектуры приняла перенос. Проверила отсутствие межмодульных зависимостей сервисов, идентичность миграции и сохранение транзакционных гарантий

## Оставшаяся работа

Подключить предметные маршруты Rental и контракты Source и Payment. Реализовать захват и обработку задач, кэши, перенос истории, прикладные метрики и Grafana. Нагрузочный прогон проводится после слияния срезов.
